# The data campaign

One long Kaggle session (GPU T4 x2, ~11 h) that decodes many models over many datasets, keeps every
candidate, and turns them into the statistics the paper needs. Code: `src/campaign/`. Notebook:
`notebooks/kaggle_campaign.ipynb`, generated by `tools/build_campaign_notebook.py`, which embeds every
source file so a notebook version is a complete, pinned record of what ran.

## Design

| factor | levels |
|---|---|
| model | Whisfusion v1 (masked diffusion), Drax-v1 (discrete flow matching); controls Whisper-small, Whisper-large-v3-turbo (autoregressive), Parakeet-CTC-1.1B (one-step parallel) |
| data | LibriSpeech dev-clean/dev-other (tuning only), test-clean, test-other; Open ASR Leaderboard AMI, Earnings22, VoxPopuli, GigaSpeech, SPGISpeech, Common Voice; FLEURS en; SLR83 UK/Irish accents; test-clean + babble 10/5/0 dB and white 5 dB; FLEURS de/fr/es/it/pt (Drax) |
| candidates | Whisfusion K=32 (PDD, 4 steps); Drax K=32 at the main temperature plus 4 at T=0.1 (its standard decoding); Whisper greedy, beam-8 n-best, 16 samples at T=0.6; CTC greedy and 32 sampled paths |
| ablations | Drax temperature 0.1..2.0 and steps 4..32; Whisfusion steps 8 and first-step sampling |

Every utterance is filtered the same way (0.8-28 s, 1-75 reference words) and every set is ordered by a
hash of the utterance id, so shard k holds the same utterances for every model and all comparisons are
paired. Clusters (speaker, meeting, call, or sentence) are kept for cluster bootstraps.

Jobs are (model, dataset shard, arms) and carry a tier. Two worker processes, one per GPU, always take
the lowest tier that is ready; if the session ends early every cell has the same depth, rather than a
few complete cells and many empty ones. Tier 0 is dev, tiers 1-2 the first 400 utterances of every
cell, tier 3 the controls, tiers 4-5 more ablations and more utterances.

## Drax

`campaign/drax_fast.py` drives Drax's own modules with a different loop: the encoder and the
cross-attention cache run once per utterance instead of once per candidate, the DiT blocks run in fp16
with an fp32 residual stream (bf16 is emulated on Turing), and the discrete-flow Euler step is the
reference solver's, written without the one-hot velocity. It also returns per-token probabilities,
which the public `Transcriber` does not, so confidence selection and confidence-weighted ROVER work
for Drax too.

## Outputs

`/kaggle/working/campaign/`:

| file | what |
|---|---|
| `dumps.tar` | `dumps/<job>/<arm>.jsonl.gz`, every candidate in the dump_candidates.py schema plus `lang`, `cluster`, `model`, `arm`, `encode_s`, `decode_s` |
| `results/per_utt_k.parquet` (and `.csv.gz`) | one row per (model, set, arm, utterance, k): edit counts of every method, reference length, diversity, timing; the input for any further statistics |
| `results/grid.parquet` | ROVER (alpha, eps, gamma) and conf+lambda*MBR grids at the main k |
| `results/cells.csv` | corpus and mean-utterance WER of every method per cell and k, legacy and Whisper normalisation |
| `results/contrasts.csv` | paired contrasts within an arm: delta, utterance and cluster bootstrap CIs, Wilcoxon p, wins/ties/losses |
| `results/cross_arm.csv` | composition against each model's standard decoding |
| `results/tuned.csv` | parameters picked on dev, reported on test |
| `results/meta_analysis.csv` | random-effects pooling over test sets |
| `results/timing.csv` | s/utt, encoder/decoder split, RTF, ms per candidate, ROVER CPU ms, peak memory |
| `results/campaign_summary.json`, `results/REPORT.md` | everything above in one file, and readable |
| `manifests.tar`, `state.tar`, `logs.tar`, `analysis.tar` | provenance |

## What is checked in

`results/campaign-2026-09-20/` is the whole of both sessions, merged, so every number can be
recomputed without a GPU and every claim traced back to the run that produced it.

| path | what | size |
|---|---|---|
| `dumps/<job>/<arm>.jsonl.gz` | the raw data: every one of the ~695,000 candidate transcripts, with per-token confidences, timings and the reference | 41 MB |
| `per_utt_k.parquet` | one row per (model, set, arm, utterance, k); the input to every table below | 6.3 MB |
| `grid.parquet` | the ROVER and conf + lambda*MBR grids at the main k | 1.5 MB |
| `manifests/<set>.jsonl.gz` | which utterances were used, in order, with cluster ids | 1.9 MB |
| `logs/round{1,2}/` | the Kaggle console log, both lane logs, the prep log and one log per worker | 0.6 MB |
| `provenance/jobs.jsonl` | one line per job that ran: wall time, encode and decode seconds, peak memory, status | 146 lines |
| `provenance/` | the plan, config, environment and dataset metadata of each session | |
| `tables/`, `figures/`, `REPORT.md`, `campaign_summary.json` | the analysis | 2 MB |

```bash
PYTHONPATH=src python tools/paper_tables.py .          # from the campaign directory
PYTHONPATH=src python tools/fig_cost_quality.py .
```

Both read `per_utt_k.parquet` only. To go further back, the dumps are self-contained: each line is
one utterance with its K candidates, so `campaign.analysis` can be rerun end to end on CPU.

Methods in the tables: `first` (one decode, no selection), `conf`/`minconf`/`logprob` (model score),
`mbr`, `cm05`/`cm15` (conf + lambda*MBR), `rover_freq` (one vote each), `rover_c` (vote share mixed
with word confidence, alpha 0.5, eps 0.7), `rover_cg` (the same with near-duplicates sharing a vote,
gamma 0.5), `oracle_cand`, `oracle_comp`, `control` (oracle_comp with unrelated alternatives), `anti`.
Deltas are WER(a) - WER(b) in points, positive when b is better.

## Re-running

```bash
python tools/build_campaign_notebook.py --variant full --user <kaggle-user> --kernel_dir /tmp/k
kaggle kernels push -p /tmp/k
# afterwards
kaggle kernels output <kaggle-user>/candidate-composition-campaign -p results/campaign
cd results/campaign/campaign && for t in *.tar; do tar xf $t; done
PYTHONPATH=src python -m campaign.aggregate --root results/campaign/campaign   # re-aggregate offline
```

Variants: `cpu` (no accelerator, tiny, every code path; free), `smoke` (T4 x2, ~50 min, every model and
job kind on a few utterances, Drax temperature calibration and an fp16/bf16 check), `full`, and `round2`
(the controls, Drax at its dev-tuned temperature, and the Whisfusion K=64 job).

Sessions are poolable: shard k of a set is the same utterances in every session, so

```bash
python tools/merge_campaigns.py out/run1/campaign out/run2/campaign --out out/merged --aggregate
python tools/paper_tables.py out/merged
python tools/fig_cost_quality.py out/merged
```

rebuilds every table and figure over both runs at once.
